# 自动执行流程与人工确认点

本参考定义从填好的商品 Excel 到最终视频的自动执行流程。除以下三处外，不要求用户手动操作：

1. 用户先在 Excel 填写商品事实和本机真实商品图片路径，并在对话里提供工作簿路径；只有一行有效 SKU 时自动选择该行。多行有效时，默认处理所有完整且未跳过行，不额外要求逐行选择；若输入明确指定 SKU，则只做该 SKU。
2. Excel 和 SKU 验证成功后，询问一次本轮使用的不鸣 AI 模型和分辨率，再继续自动策划和生成首帧。本轮已明确提供这两个参数时直接沿用，不重复问。当前实现为 `omni-1.1` 与 `720P`、`1080P`、`4K`；若用户选其他不鸣模型，先自动查阅不鸣网站的相应 API 文档并适配验证。资料不足时报告具体限制，不猜接口、不擅自换服务或模型。
3. 自动生成所有本轮需要的静态首帧后，在 Codex 中展示图片并暂停。等用户反馈要修改，或明确批准并要求下一步；在此之前不得生成/提交任何图生视频任务。

## 阶段顺序

### A. 读取 Excel 并建立项目

- 按 SKILL.md 的“Excel 来源定位”选择已填 Excel。用户指向本 Skill 资产时，读取当前 Skill 自身的 `assets/product-input-template.xlsx`，并先报告绝对路径、工作表、SKU 和行号；模板空行不能当商品信息。工作簿必须有“产品输入”表、所需列、有效 SKU/产品名/产品信息/卖点/图片路径/视频数量。用户本轮明确的制作数量可通过 `--sku <SKU> --video-count <数量>` 覆盖到项目配置，保留 Excel 原值。确认本机路径存在、图像可以打开。校验无阻塞后，先问一次模型和分辨率；用户选择覆盖 Excel 中同名可选列。
- 把用户选择另存为 SKU 项目的 `production-config.json`（不要改写原始 Excel 镜像）：`provider: "buming-ai"`、用户实际选定的 `model`、`resolution`、`aspect_ratio: "9:16"`、`spoken_language: "en-US"`。Excel 中可选模型/分辨率只作预填建议，用户回复优先。
- 执行 `node scripts/read-product-input.mjs <Excel路径>` 读取和校验；用户给定 SKU 时仅处理该 SKU。批量时跳过显式标记“跳过”的行，对无效行报告具体缺项。
- 初始化用户指定 SKU 时加 `--sku <SKU>`。未指定 SKU 的批量运行跳过“已完成”和“跳过”行，避免重复制作历史成片。
- 执行 `node scripts/initialize-batch-projects.mjs --excel <Excel路径> --projects <项目根目录>` 建立 SKU 文件夹和 `product-config.json`。默认项目根目录为当前仓库根目录下的 `projects/`，恢复历史项目时则使用其原有实际路径。单条视频的五镜头文件在 SKU 根目录；视频数量大于 1 时，每条视频独立放入 `video-01/`、`video-02/` 等子目录，分别生成和执行五镜头任务。
- 核对商品事实与图片。安装、插入、夹持、磁吸、卡扣、套入、连接、支撑、旋转等空间连接镜头必须有显示商品主体和连接结构的真实 30°–60° PoseMaster；不具备时只阻塞依赖该关系的镜头，不可由图像模型补造产品证据。

### B. 自动策划与静态首帧

- 按 [统一制作计划](structured-plan.md) 为每条视频初始化并填写 `production-plan.json`。模型负责事实核对与创作，程序按固定字段和跨字段关系校验；planning 编译派生方向卡、脚本、P/R、静态提示词和 `first-frame-jobs.json`。对视频数为 N 的行，维护 N 份独立计划，每份 S01–S05。一个视频将五张首帧放在 `first-frames/`；多个视频分别放在 `video-NN/first-frames/`。
- 策划前按 [高停留钩子与产品证明设计](hook-and-proof.md) 生成并比较至少三个不同画面机制的开场。首帧审核不仅看 AI 画面是否真实，也要看钩子是否有停留力、S02 是否迅速接回商品、S03–S04 是否能用真实演示兑现期待。不要因“像自然 Vlog”而把视觉反差一律改回平淡的痛点口播；用可实现的构图/动作/剪辑保留创意强度。
- 在具备 ImageGen 工具时，调用图像生成工具生成首帧，而不是停留在提示词。逐镜头生成独立竖版 9:16 图片，不要把五格拼图当五张首帧；使用一致的人物、穿着、空间与自然光设定。若需要跨镜头人物/环境锚点，先生成锚点并在后续镜头引用。商品身份与 PoseMaster 来自真实产品图片，绝不让模型重设计商品。
- 保存到对应视频目录下 `first-frames/S01.png` 至 `S05.png`。如实际路径不同，复制后验证文件并修改统一计划的 `first_frame`，再 planning 编译；用户指定 S020.png 等替换图也按此回填。保持原图，不用图像编辑去修造产品结构。
- 检查每张图是否对应首帧起始状态、钩子构图、产品结构/比例/坐标轴、手部关系、9:16 构图、生活环境连续性和美区自然手机 Vlog 质感。真实感应来自自然窗光、普通居住空间、肤色与材质细节、可信生活动作；钩子的创意可夸张，表演/商品接触/空间关系仍要成立。避免过度磨皮、塑料质感、漂浮/多余物体及会破坏可信度的伪造产品效果。
- 完成全部图片后，把图片嵌入 Codex 回复（使用可见的绝对路径），按 S01–S05 标注并写实际文件路径。此时将状态记为 `generated` / `awaiting_user_review`，而不是 `approved`，清晰询问“需要修改哪张，还是确认继续？”然后停止。不要顺带生成视频提示词 JSON 或调用 API。

### C. 用户批准后自动执行图生视频与成片

- 收到明确“继续/可以/不用修改，开始下一步”等确认后，才标记静态首帧 `approved`。若用户要求修改，仅重做相关首帧并再次完整展示；用户再次批准后方可继续。
- 人工验收通过后直接从统一计划调用 `scripts/record-first-frame-approval.ps1 -ProjectDirectory <视频目录> -UserConfirmation <用户本轮确认原话>`，记录模型/分辨率、五张图 SHA256 和视觉计划/参考素材哈希，不需要预先写视频任务。不得在用户确认前调用。替换图片或更改视觉计划后必须重新展示并取得确认。
- 在同一计划填写每镜头 `motion_prompt`，video 编译自动组合准确美式英语台词和口播方式，派生 `image-to-video-prompts.md` 和 `image-to-video-jobs.json`。生成秒数、最终保留秒数、起剪点均从计划读取；镜头合计 15–20 秒。禁止手改派生任务、Markdown 或另造秒数表；需要修改时改计划后重编译，提交/修剪会拦截过期任务。
- 当前不鸣 AI Omni 1.1 实现只支持 5 条任务、9:16 和接口已支持的分辨率，参考 [不鸣 AI Omni 1.1](providers/buming-omni-1.1.md)。执行前先 dry-run 校验任务、首帧文件大小/路径、分辨率和任务指纹，检查 `BUMING_API_KEY` 或本机 `.secrets/buming-api-key.txt` 是否存在；永不把密钥显示、回写到状态文件或命令日志。缺凭据时停止并给本机配置方法，不让用户在聊天里粘贴密钥。
- 在首帧获批后，用户已通过选择模型/分辨率并要求自动完成来授权本轮提交。对每个视频目录分别调用不鸣 AI API 创建任务，保存 `task_id` 与请求指纹，按接口终态轮询，成功后下载到对应 `videos/`。同指纹已有任务时恢复/复用；网络超时或轮询失败只重试查询，不能新建重复任务。明确失败时不自动重复扣费。
- 下载后检查文件可读与时长。依据 `edit_duration_seconds` 将 API 原始视频修剪为 `videos/edit-ready/S01.mp4`…的中间成片；API 原始下载不得覆盖。拼接生成首剪 `videos/final-video.mp4`，五镜头按 S01–S05 排序。最终时长不在 15–20 秒或任一镜头缺失时不得报完成。

### D. 首剪质检、二次优化与交付复检（强制）

首剪只是待审核版本，不能直接作为交付成片。按镜头检查最终拼接画面和口播：

1. 首剪后必须调用 `scripts/run-faster-whisper-qa.ps1 -VideoPath <final-video.mp4> -OutputPath <视频目录>/asr-transcript.json`。该入口固定使用 `%LOCALAPPDATA%\faster-whisper\.venv\Scripts\python.exe`、faster-whisper 1.2.1、`base.en` 模型缓存和 CPU int8，转写英文并输出词级起止时间。用户首次部署时运行 `scripts/setup-faster-whisper.ps1`；setup 未完成、路径/版本错误或转写失败时，停止交付并报告，不能静默退化到另一个 ASR 或人工声称通过。Codex 必须读取实际生成的 JSON，将识别词和时间点与 `production-plan.json` 的 `dialogue` 逐句比对，并实际试听低置信、不清楚或疑似切断位置。
2. 检查台词是否被镜头边界切断、口播相对画面是否无故延迟、词句之间是否出现破坏表达的长静音/空档。除非脚本明确设计停顿，镜头开始后约 0.5 秒仍未起口、句间静音超过约 0.8 秒，或任何目标词缺失/尾音被截，均应作为复查信号；结合画面动作、台词意图和实际试听判断，不能机械删掉有意留白。
3. 发现上述问题或画面/音频连续性缺陷时，必须执行本地二次剪辑并重新拼接。优先用原始生成素材修复：延长/缩短入出点；将原素材中完整口播片段移至合适时间；压缩不必要静音；必要时用同步的画面切点隐藏音频跳接。保持屏幕动作、人物口型和声音来源一致。FFmpeg 等编辑器只执行给定剪辑，不负责判断台词或节奏；Codex 根据脚本、ASR 时间戳、预览和试听决定修改点。不要因可本地修复的问题直接重新付费生成。
4. 二次剪辑后重新导出并再次调用同一 ASR 入口，复检完整成片：核对台词、词级时间、实际试听、画面、转场和口型/动作；再用 `scripts/validate-final-video.ps1` 验证文件、音轨、9:16 画幅及 15–20 秒时长。若发现仍可修复的问题，继续修正并重新 ASR；若源素材或工具限制导致无法通过，记录具体镜头、未通过项和原因，不标记完成、不把未通过版本作为最终成片交付。
5. 在 SKU 项目目录保存 `final-quality-check.json` 或等效记录，至少包含每句识别结果、问题与修正、最终复检状态、技术参数，以及实际试听/视觉预览是否完成。只有最终复检通过才将状态标记为 `completed` 并交付 `final-video.mp4`。

- 审核并报告每个镜头生成状态、失败/重试原因、所用模型/分辨率/时长、成片路径和复检结果；只有文件真实存在且最终复检通过才标记 `completed`。

## 执行命令与任务文件

以下命令由 Codex 执行，用户无需打开终端。以 Skill 目录为工作目录，传入绝对路径：

```powershell
.\scripts\run-buming-omni-1.1-batch.ps1 -ProjectDirectory <视频目录> -DryRun
.\scripts\run-buming-omni-1.1-batch.ps1 -ProjectDirectory <视频目录>
```

只有 dry-run 的 `ready` 为 true 才能执行第二条。任务文件由统一计划编译，顶层含 `schema_version`、`plan_sha256`、`model`、`aspect_ratio`、`resolution`、`jobs`；`jobs` 必须各含一次 S01–S05。每镜头包含 `shot`、实际 `first_frame`、整数 `duration_seconds`、正数 `edit_duration_seconds`、`trim_start_seconds`、中文 `prompt`、精确英语 `dialogue` 及 `request_fingerprint`。保留区间必须落在生成时长内；规划成片可留少量余量，避免编码尾帧使成片超过 20 秒。

下载和拼接完成后，实际预览各镜头和成片、试听英语口播：检查商品结构、连续性、自然 Vlog 质感、英语是否完整且未被剪断、声线及音量是否连续。必要时修改统一计划的 `trim_start_seconds`/保留秒数，video 重编译后重新修剪和拼接；生成指纹不变时复用原视频，不重提任务。`ffprobe` 的音轨存在检查不能代替对白和画面审核；无法检查的项目如实标为未核验。技术性缺陷可在本地修复，需重新付费生成的缺陷则记录具体镜头，保留现有结果。

## 自动化边界

- Codex 工具不可用、API 密钥不存在、模型或分辨率不在实现范围、产品事实有阻塞冲突、PoseMaster 缺失、或者接口返回硬错误时停止对应分支并记录原因，不要把执行责任默默转回给用户做工具操作。
- 图像生成与首帧审核分属两个确认阶段；用户要求审核的首帧检查点必须保留。
- 可恢复的运行失败应优先继续现有任务或使用原任务 ID，不重复创建已计费任务。只有用户明确要求重做某镜头时，才以新版本提交该镜头。
