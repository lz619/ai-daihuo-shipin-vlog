# 从产品输入到自动成片与部署说明

## 这套 Skill 现在能做什么

本 Skill 的目标是：根据 Excel 中已经核实的商品信息，为一个 SKU 建立五镜头美国 TikTok 日常 Vlog 带货视频，并在 Omni 1.1 视频全部生成后自动拼接为一条竖版成片。

当前 SKU `001` 已完成的最终成片位于：

`projects\001\videos\final-video.mp4`

当前成片由 S01、S02-v2、S03-v2、S04-v3、S05 自动顺序拼接而成；视频为 720×1280，包含原始口播音频，总时长约 26 秒。

## 完整流程

| 阶段 | 输入 | 机器执行内容 | 当前是否需要人工参与 | 产出 |
|---|---|---|---|---|
| 1. 商品事实输入 | 完整 Excel 商品事实卡、真实商品图片 | 读取所有已填写 SKU 行，为每行建立独立 `product-config.json` | 是：必须先确保 Excel 与商品图真实、完整 | 各 SKU 项目文件夹 |
| 2. 创意与分镜规划 | Excel 事实与商品图 | 生成视频方向卡、五镜头脚本、连续性规则、最小素材计划 | 否 | 方向卡、五镜头脚本、素材计划 |
| 3. 连续性锚点图 | 人物、车辆/场景、商品图与中文提示词 | 当前由 GPT 网页生成并保存 | 是：需要生成并确认锚点图 | `anchors\R01-...png` |
| 4. 五张静态首帧 | 锚点图、商品图、每个分镜的中文静态提示词 | 当前由 GPT 网页生成并保存；机器记录路径和审核结果 | 是：需要生成、保存并确认 S01-S05 首帧 | `first-frames\S01.png` 至 `S05.png` |
| 5. 图生视频提示词 | 已审核首帧、五镜头脚本 | 生成中文图生视频提示词；英文仅保留为美国英语口播原句 | 否 | `image-to-video-prompts.md` |
| 6. Omni 1.1 图生视频 | 每个 SKU 自己的五张首帧、`image-to-video-jobs.json`、API 密钥、用户对本批费用的明确授权 | 逐 SKU 提交、轮询、下载五条视频 | 已支持自动化；每一批新的付费提交仍需用户明确授权 | `videos\S01...S05...mp4` |
| 7. 返工版本管理 | 用户对某镜头的明确修改要求 | 仅重新提交指定镜头；新文件保存为 `S02-v2.mp4`、`S04-v3.mp4` 等，不覆盖旧版 | 返工决定需要人工提出；提交、下载可自动 | 最新版本分镜 |
| 8. 自动剪辑成片 | 五条已生成视频 | 自动选每个镜头最新版本，按 S01 → S05 拼接、统一编码、保留音频 | 否 | `videos\final-video.mp4` |
| 9. 可选后期 | 已拼接成片、已授权 BGM/字幕规则 | 可自动混入 BGM、生成字幕、导出多个版本 | 需要先确定音乐来源与剪辑规则 | 带 BGM/字幕的最终版本 |

## 当前已经自动化的部分

### 图生视频到最终成片

先运行以下命令检查所有 SKU 是否已具备任务文件和五张首帧；该命令不调用 API：

`scripts\run-ready-video-batch.ps1`

确认后，当五张首帧已经存在、API 密钥已配置，并且用户明确授权提交一批 Omni 1.1 任务后，执行：

`scripts\run-ready-video-batch.ps1 -Submit`

也可只处理一个 SKU：

`scripts\run-buming-omni-1.1-batch.ps1 -ProjectDirectory .\projects\你的SKU`

它自动完成以下事情：

1. 读取每个 SKU 自己的 `image-to-video-jobs.json`，提交 S01-S05 的 Omni 1.1 图生视频任务；
2. 每隔一段时间查询任务状态；
3. 下载成功视频；
4. 不覆盖老版本。若已有 S02.mp4，会保存为 S02-v2.mp4；
5. 自动选择每个镜头版本号最高的文件；
6. 调用 FFmpeg 输出 `videos\final-video.mp4`；
7. 将可续跑的任务 ID、首帧指纹和下载路径写入 `video-task-state.json`，未改首帧/提示词/时长/分辨率时不重复扣费。

单独只拼接、不重新生成视频时，使用：

`scripts\assemble-final-video.ps1`

它不调用 AI、不消耗 AI token，也不产生 Omni 生成费用。它只在本机用 FFmpeg 处理已有 MP4 文件。

## 哪些步骤仍然需要人工，为什么

### 1. Excel 商品事实卡

这是所有商品宣称的唯一依据。机器可以读取，但不能凭常识补齐商品是否包含某个配件、按钮具体功能、性能阈值或安全效果。Excel 填错会导致整条视频都错，因此应由商品负责人提供和确认。

### 2. 人物锚点图与五张静态首帧

当前采用 GPT 网页人工生成，是为了先确认人物、衣服、车内环境、商品结构、手部关系、商品位置都正确。尤其像胎压监测仪必须在仪表台顶部，而非杯架或挡把附近，这类错误只靠文字提示仍可能发生。

### 3. 新一批视频生成的费用授权

Omni 1.1 是付费外部服务。脚本可自动跑完一批，但每次真正向该服务提交新任务前，仍应由你明确说“按某分辨率提交这一批”，以防误触发费用。

### 4. 最终画面质量验收

机器可检查文件是否存在、时长、画幅、音视频流；但不能可靠保证人物没有变脸、手指没有畸形、商品摆放语义正确、口型是否自然。建议至少抽查每个 SKU 的最终成片，或先抽查一个样本 SKU 再批量放行。

## 静态首帧能否继续自动化

可以，但推荐走“图片模型 API 自动生成”，而不是模拟点击 GPT 网页。

### 推荐方案：接入图片生成 API

自动流程可以变为：

1. 读取 Excel、商品图与方向卡；
2. 自动生成 R01 连续性锚点图；
3. 基于 R01 和商品图，自动生成 S01-S05 首帧；
4. 保存到对应 SKU 的 `anchors` 和 `first-frames` 文件夹；
5. 用规则检查图片尺寸、文件完整性、是否出现文本；
6. 自动提交 Omni 1.1、下载并拼接。

为实现该方案，需要你选定图片供应商并提供该供应商的 API 密钥。若使用 OpenAI 图片 API，还要确认所用账户、模型、生成成本、参考图能力，以及是否允许把商品图和人物锚点图发送给该 API。

### 不推荐方案：自动操作 GPT 网页

技术上可以用浏览器自动化模拟上传和点击，但网页界面、登录状态、风控、图片审核和会话上下文容易变化，失败后不易无人值守恢复，也不适合作为稳定的商业批处理主流程。网页更适合人工抽样确认；量产应该走明确的 API。

### 可进一步自动化的环节

| 环节 | 自动化方式 | 需要你先定下的规则 |
|---|---|---|
| BGM | Excel 已可为每个 SKU 保存 BGM 文件路径；下一步可按固定授权音乐、音量和淡入淡出规则接入 FFmpeg | 音乐文件、商用授权、音量比例、是否保留原声 |
| 字幕 | 由已有英文台词直接生成 SRT/ASS，再烧录或输出可编辑字幕文件 | 字体、位置、语言、是否中英双语 |
| 成片长度 | 每镜头按脚本的“保留时长”自动裁切，而不是完整拼接 | 是否允许裁切台词、每镜头目标秒数 |
| 多 SKU 批跑 | 遍历 Excel 的多行 SKU，逐个建项目、生成、下载、拼接 | 并发数量、每天预算上限、失败重试策略 |
| 质量初检 | 自动检查分辨率、时长、音轨、文件大小、是否缺镜头 | 人物/商品语义错误仍建议人工抽检 |

## 费用与 token 的边界

| 动作 | 是否消耗 AI token | 是否产生外部费用 |
|---|---|---|
| Agent 读取 Excel、写提示词、更新脚本 | 会消耗当前 Agent 对话/工作 token | 通常无单独媒体费用 |
| 执行 PowerShell、FFmpeg 拼接、混音、生成字幕文件 | 不消耗 AI token | 不产生 AI 生成费用 |
| Omni 1.1 图生视频 | 不以本 Agent token 计费 | 会产生不鸣 AI 的视频生成费用 |
| 图片模型 API 自动生成首帧 | 不以 FFmpeg token 计费 | 会产生所选图片 API 的生成费用 |
| 让 Agent 自动做视觉语义审核 | 会消耗 Agent token | 视所用模型/平台而定 |

## 明天迁移到公司电脑：推荐部署方式

### 最稳妥的共享文件夹结构

将整个 `us-vlog-product-video` 文件夹复制到公司电脑的固定位置，例如：

`D:\AI-Skills\us-vlog-product-video`

必须一并复制：

```text
us-vlog-product-video/
  SKILL.md
  references/
  scripts/
  assets/
  projects/              （如需要继续当前 SKU 001）
  docs/
```

不要复制个人 API 密钥。公司电脑上应由你或管理员重新创建：

`D:\AI-Skills\us-vlog-product-video\.secrets\buming-api-key.txt`

文件只放一行新的 API 密钥；或者在公司电脑设置 `BUMING_API_KEY` 环境变量。不要把密钥放进 Excel、SKILL.md、聊天记录、Git 仓库或共享网盘。

公司电脑还需要安装：

1. PowerShell 7 或可运行 PowerShell 脚本的环境；
2. FFmpeg（用于拼接和后续 BGM/字幕）；
3. Node.js（用于读取 XLSX）；若用 Codex，脚本会自动使用 Codex 已安装的表格运行库；
4. 能访问不鸣 AI API 的网络；
5. 使用的 Agent（Codex、WorkBuddy 等）具备读取该文件夹和运行脚本的权限。

### 给 Codex / ChatGPT desktop

当前文件夹可以作为本地 Skill 直接给 Agent 阅读和执行。若要让公司电脑里的 Codex/ChatGPT desktop 可发现、可安装、可更新，推荐下一步把它封装为“可移植插件”：

```text
插件根目录/
  plugin.json
  skills/
    us-vlog-product-video/
      SKILL.md
      references/
      scripts/
      assets/
```

然后通过本地 marketplace 或公司 Git 仓库安装。这样可以版本管理，并让多位同事使用同一份 Skill。OpenAI 的官方插件说明确认：插件根目录可包含 `skills/`、`mcp.json`、资源文件；本地 marketplace 可在 Codex/ChatGPT desktop 中安装和启用。

已生成可直接携带的包：`portable-plugin\us-vlog-product-video-codex-plugin.zip` 与 `portable-plugin\us-vlog-product-video-workbuddy-skill.zip`。两包均不含 `.secrets`、项目视频和本机临时运行环境。

### 给 WorkBuddy

WorkBuddy 的 Skill 目录同样支持 `SKILL.md`、`references/` 和 `scripts/`，但需要补充它自己的元数据，例如中文/英文描述、分类、版本、作者。不要直接假设 Codex 包可无修改导入；本目录会同时提供一个 WorkBuddy 专用包装，再从 WorkBuddy 的技能市场/导入入口安装。

### 给其他智能体

可分为三类：

1. **支持 Agent Skills / SKILL.md 的智能体：** 复用核心目录，并按对方所需的前置元数据做小型适配。
2. **只能读项目说明的智能体：** 将 `SKILL.md` 与 `references` 作为项目规则，让它执行 `scripts` 中的 PowerShell 命令。
3. **不能运行本机脚本的云端智能体：** 它们只能做规划或生成提示词；视频提交、下载、FFmpeg 拼接仍需在有本机执行能力的公司电脑或服务器上运行。

## 建议的公司落地顺序

1. 在公司电脑复制 Skill，安装 FFmpeg，重新配置 API 密钥；
2. 使用一个测试 SKU 跑通“首帧已存在 → 五视频 → 自动成片”；
3. 固定 BGM、字幕、成片长度等输出规范；
4. 再接入图片 API，实现首帧自动生成；
5. 将 Skill 封装为可移植插件，放入公司 Git 仓库或私有 marketplace；
6. 设置单次并发数、每天预算和失败告警后，再开始多 SKU 批量生产。
